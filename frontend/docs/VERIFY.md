# Проверка UI (BR-813)

## Что защищаем

Агент может успешно нажать кнопку и не заметить, что она стала выше или рядом пропала иконка. Поэтому результат — не фраза «посмотрел скриншот», а измерения и сравнение с базовой версией.

Три независимых слоя:

- Storybook/Vitest: состояние и поведение компонента, a11y и геометрические инварианты.
- `verify:ui`: реальные страницы с MSW, сравнение геометрии/иконок/цветов/типографики и пикселей с базовым commit.
- `verify` skill: реальные действия по изменённому сценарию, просмотр before/after, сравнение с Figma и разбор отличий. Автоматика не определяет, красив ли новый дизайн или соответствует ли он макету.

## Запуск

Node 24, pnpm из `package.json`. Из `frontend/`:

```sh
pnpm install --frozen-lockfile
pnpm exec playwright install chromium
pnpm verify:install
pnpm lint:tokens
pnpm test:verify
pnpm verify:ui
```

`verify:install` устанавливает локальные hooks; чужой `core.hooksPath` не перезаписывается. Установка не глобальная — каждый клон настраивается отдельно.

По умолчанию база — `HEAD`. Runner создаёт временный detached worktree, устанавливает зависимости с его lockfile, запускает два dev-сервера на свободных loopback-портах с `VITE_API_MOCKS=on`, открывает изолированный headless Chromium и закрывает свои процессы/worktree после завершения. Первая установка базы может обратиться в package registry. В CI/контейнере нужны системные зависимости Chromium (`playwright install --with-deps chromium`).

Матрица описана в `scripts/verify/scenarios.ts`: страницы home, merchant, offer, submit, verification, not-found и мобильное открытое меню; 390×844 и 1440×900, light/dark. Новая страница или значимое состояние должны получить сценарий. Это не замена проверке clipboard, offline, отправки формы и других изменённых действий реальным вводом.

```sh
pnpm verify:ui --only merchant       # диагностика, stamp не выдаётся
pnpm verify:ui --base origin/main    # полное изменение ветки перед PR
```

## Читать результат

- `.verify/report.md` — список изменений с ID, измерениями, before/after crops (слева база).
- `.verify/report.json` — машинный отчёт и причины приёмки.
- `.verify/images/` — base/head/diff и увеличенные crops: обычная страница целиком, открытый модальный overlay — в пределах viewport (фон за ним заблокирован).
- `.verify/*-server.log` — запуск серверов.
- `.verify/<scenario>.json` — исходные измерения обеих версий.

Пропавшие/появившиеся элементы, изменение размеров/позиции/стиля, новые нарушения геометрии, новые runtime-ошибки и пиксельные отличия дают exit 1. Пиксельный diff не игнорируется только потому, что геометрия уже поменялась: это могло скрыть исчезнувший соседний значок. Старые нарушения перечисляются отдельно и не объявляются исправленными.

Если изменение не требовалось задачей — исправить код и повторить проверку. Только намеренное отличие принимается по отдельному ID:

```sh
pnpm verify:ui accept 'a1b2c3=BR-123 требует увеличить выбранную кнопку до 44px'
```

Неизвестный ID, `all`, пустая причина и частичный прогон не допускаются. Не подтверждать список циклом. После правки кода или инструментов проверки отчёт устаревает. После успешного полного прогона/приёмки всех отличий создаётся `.verify/stamp.json`; он не коммитится и не редактируется вручную.

## Commit gate и границы доверия

Pre-commit сверяет staged-код с проверенным состоянием, включая инструменты проверки. Частично staged исходники не равны проверенному рабочему дереву. Prepare-commit-msg фиксирует принятые отличия в trailers. В режиме `enforce` отсутствующий/устаревший stamp блокирует UI-коммит. Режим можно явно переключить локально: `git config verify.mode observe` (диагностика), `enforce` или `off`.

Hooks — защита от забывчивости, не security boundary: владелец клона может их обойти, а автор PR может менять проверки. Проверяющий должен отдельно рассмотреть изменения runner/scenarios/rules и причины приёмки. Защищённый CI требует branch protection и доверенных workflow; локальный stamp не выдаётся за такой CI.

CI запускает token lint и регрессионные тесты верификатора, а Storybook — геометрические проверки вместе с существующими interaction/a11y-тестами. Полное сравнение с базой PR выполняется в режиме **observe**: результат указан в job summary, изображения/JSON/отчёт публикуются как `ui-verification` на 7 дней. Отличия сами по себе не блокируют CI: намеренные изменения требуют решения ревьюера. Локальный браузерный отчёт не является доказательством успешного удалённого CI.

## Дизайн-система и ограничения

`lint:tokens` запрещает буквальные CSS-цвета вне генерируемого `tokens.css`. Источник значений — DTCG в `tokens/*.json`; допустимы `currentColor`, `transparent` и `color-mix` из токенов. Это не проверка всех отступов, вариантов компонентов или соответствия Figma. Неверный baseline остаётся неверным: эталон макета проверять отдельно.

Проверка центра применяется только к контролам без отображаемого текстового содержимого. Метка ссылки, временно обрезанная контейнером или выехавшая за viewport при открытии drawer, не превращает ссылку в icon-only. При этом `display:none` и метки для скринридера размером 1×1 не исключают настоящую иконочную кнопку из проверки.

Runner ждёт шрифты после действий сценария, включая появление overlay. Модальные состояния снимаются в реальном viewport: искусственная full-page растеризация фона за фиксированным диалогом может давать отличия невидимого текста ниже экрана. Обычные состояния страниц по-прежнему сравниваются целиком; пороги pixel diff не ослабляются.

Геометрические правила — эвристики; особенно сложны line-clamp, порталы, scroll-контейнеры и оптически несимметричные значки. Текстовые ID строятся по семантике; изменение текста может выглядеть как remove/add. Цвета зависят от темы, шрифты — от доступности Google Fonts. Перед сравнением runner ждёт `document.fonts.ready`, выключает анимации и caret; недоступные шрифты нельзя выдавать за проверку нужного шрифта. Chromium/web не доказывает Safari, native/QML или GPU-поведение.

После трёх безуспешных исправлений агент эскалирует с точным сценарием, измерениями и before/after/diff. Процесс для других приложений закреплён в глобальном `ui-testing`; сам web-runner этого репозитория не тестирует inir.
